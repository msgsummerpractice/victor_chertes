== Exercise 7: Reverse Proxy with Nginx, Scalable App, and Persistence

This is the ultimate Docker Compose challenge! You will build a complete architecture consisting of a **Reverse Proxy (Nginx)**, a **Scalable Application Layer (Node.js)**, and a **Persistent Database (Redis)**.

=== Objectives

* Use Nginx to load balance traffic to multiple application containers.
* Configure services to work together in a complex setup.
* Ensure data persistence for the database using named volumes.

=== Prerequisites

* Completion of Exercise 4 (Networks), Exercise 6 (Scaling), and Exercise 6 (from Docker series - Volumes).

=== Task

1. Review the `nginx.conf` file provided in this directory. It defines an `upstream` that points to the `node-app` service on port `8081`.
2. Create a `docker-compose.yml` file that orchestrates the three services:
+
[source,yaml]
----
services:
  nginx-proxy:
    image: nginx:alpine
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf:ro
    ports:
      - '80:80'
    depends_on:
      - node-app

  node-app:
    build: .
    environment:
      - REDIS_HOST=redis-server
    depends_on:
      - redis-server

  redis-server:
    image: 'redis:alpine'
    volumes:
      - redis-data:/data

volumes:
  redis-data:
----
3. Start the application and scale the `node-app` to 4 instances:
   `docker compose up -d --scale node-app=4`
4. Open `http://localhost` in your browser.
5. Refresh the page several times. Observe the **Hostname** changing in the response. This proves that Nginx is load balancing your requests across the 4 application containers!
6. Increment the visit counter a few times.
7. Stop the entire stack:
   `docker compose down` (Do NOT use `-v` yet).
8. Start the stack again:
   `docker compose up -d --scale node-app=4`
9. Refresh `http://localhost`. Notice that the **Number of visits** was preserved, thanks to the Redis named volume!
10. Finally, clean up everything including volumes:
    `docker compose down -v`

== Learning Outcome

* Learn how to implement a production-like architecture using Docker Compose.
* Understand the role of a reverse proxy in a microservices environment.
* Combine all previously learned concepts: services, build, volumes, scaling, and networks.
